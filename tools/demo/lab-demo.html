Notation used in these puzzles
a ← b
assigns. = compares and never assigns.
for i ← 0 to 3:
runs i = 0, 1, 2, 3. A range includes both ends, so the bound is the last index visited, not a count.
for i ← 3 down to 0:
runs the same four values, counting down.
x[0], T[i, j]
subscripts start at 0. Arrays take one, tables take two.
x[0..n−1]
a slice, ends included.
a · b, a − b
multiplication and subtraction. In a blank you can type * and - instead.
i ≠ j, i ≤ j, π
likewise !=, <= and pi in a blank.
length(x)
along with abs, sqrt, cos, sin, exp, max, min, sum, zeros and solve.

Two things differ from Python on purpose. Dividing by zero stops the program instead of returning infinity, and a subscript outside the array stops it instead of wrapping to the other end.

How this lab was built

The puzzle engine, the build pipeline and the first drafts of the writing were built with the help of a large language model. I checked every mathematical claim, every hint and every wrong-answer message before it went up, and anything still wrong in them is mine. The Leiden Declaration on Artificial Intelligence and Mathematics asks for this kind of disclosure.

Nothing on this page calls an AI service. Your work is checked by a small interpreter running in your browser, your progress is saved on your own machine, and no request leaves the page.

Using AI on this lab

You could paste any of these puzzles into a chatbot and have the answer in seconds. The answer isn't what the lab is for. The blocks are written for you already, so the work left is deciding what order they go in and why, and that is the part that transfers to an algorithm you haven't seen before.

Use whatever helps you understand something you're stuck on. Don't use it to skip the reasoning.
